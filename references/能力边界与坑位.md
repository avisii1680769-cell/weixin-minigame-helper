## 二、硬约束（不可绕过）

### 1. 预览端口写死 3847

代码中端口是常量，无环境变量或参数可改。被占用只能杀掉占用进程。

### 2. 服务只监听 IPv6 回环 `[::1]`

实测 `netstat` 显示 `TCP [::1]:3847 [::]:0 LISTENING`。
后果：

- `http://127.0.0.1:3847` **不通**（IPv4 回环未监听）
- 容器外、宿主、外部域名**都不通**
- 只能通过同主机的 IPv6 回环访问

这是本移植版必须附带反向代理的根本原因。

### 3. 截图 / 日志强依赖「浏览器已连接」

`capture_screenshot` 与 `get_logs` 的数据都来自**预览页面内的运行时**：

- 日志：由页面注入的 `wx-compat` 拦截器捕获后通过 SSE 上报
- 截图：MCP 向已连接的预览客户端请求 canvas 快照

**没有浏览器打开预览页时，两者都不可用**，`capture_screenshot` 会明确报
`No connected preview clients`。

这与普通「服务端渲染截图」工具不同——它不是无状态截图 API。

### 4. `preview_url` 工具不存在

WorkBuddy 插件的 `SKILL.md` 与 `commands/*.md` 里反复让 AI 调用 `preview_url`，
但这个工具**不在 MCP 包的工具列表中**（19 个工具里没有）。

它是 WorkBuddy 宿主提供的能力（宿主内置浏览器）。

移植后必须替换为：

- Playwright / Puppeteer 无头浏览器，或
- 直接把 URL 交给用户 / 其他浏览器工具打开

### 5. 真机预览与发布本质是服务端 API

`real_device_preview` / `publish` 走 `miniprogram-ci`，不依赖浏览器，
**无头环境可正常使用**（前提是配置齐全）。

但它们生成的二维码与结果会推送到**已连接的预览页面**上展示。
纯无头环境需要自行处理这个回显（或从工具返回值里取信息）。

## 三、容易被误判为故障的正常现象

| 现象 | 真实原因 |
|---|---|
| 预览页 Console 显示 `0 条`，但实际有日志 | 面板需要切换到对应视图；实际网络请求 `/api/logs` 是 200 |
| `get_logs` 返回 `No logs found` | 浏览器未连接，或游戏尚未产生日志 |
| 代理能返回 200 但页面白屏 | 预览服务未启动（`run_game` 没调），代理返回的是 502 文案页 |
| 截图返回极小图片（几 KB） | 正常，纯色 canvas 压缩后本来就小 |
| `run_game` 重复调用不报错 | 设计如此，幂等 |

## 四、依赖结构

上游包依赖：

| 依赖 | 作用 | 跨平台注意 |
|---|---|---|
| `esbuild` | 打包小游戏代码 | **平台相关**，迁移后须重装 |
| `express` | 预览 HTTP 服务 | 纯 JS |
| `chokidar` | 文件监听 | 纯 JS（`@parcel/watcher` 有原生部分） |
| `miniprogram-ci` | 真机预览 / 上传 | 含原生模块，注意平台 |

**跨平台迁移最大的坑是 esbuild**：Windows 上 `npm install` 只会装
`@esbuild/win32-x64`，搬到 Linux 会报 `Cannot find module @esbuild/linux-x64`。
`setup.sh` 已加入平台校验与自动重装。

完整 `node_modules` 约 330 MB。

## 五、没有验证过的地方

诚实标注，以下未实测：

- Unity / Cocos / WebGL 引擎的导出包能否直接预览（官方称支持，未验证）
- 真机预览与上传（需要真实 AppID + 密钥 + IP 白名单，本次未配置）
- Linux / MUSE 环境下的实际运行（本包在 Windows 上验证，Linux 步骤为推导）
- 高负载下 SSE 长连接的稳定性

首次在 MUSE 部署后，建议先跑 `node bin/smoke-test.js`，再拿
`examples/minimal-game` 做一次完整验证。
